# StoryLens 0.1.0 — проверка новой реализации

Обновлено: **20 октября 2026 года**. Старый прототип не использовался. Данные проверок — вымышленные. Это результаты на текущем Windows-компьютере, не сертификат безопасности.

## Оценка публичного предварительного выпуска

Версия пригодна для открытой пробной эксплуатации с отдельными резервными копиями. Основа соответствует упрощённому приложению: текст и главы доступны сразу, материалы открываются по запросу, план и хронология вынесены отдельно. Существенные ограничения — неполное сохранение оформления Word, отсутствие проверки на чистой Windows и длительной работы с реальными книгами. Поэтому 0.1.0 публикуется как **preview / prerelease**, без заявления о стабильности.

Перед публикацией выполнено:

- 2 теста очереди записи, 9 Rust-тестов и 10 сценариев Edge/Playwright прошли; TypeScript/Vite production build и Clippy `-D warnings` прошли. Предупреждения среды о недоступных hard links в incremental cache не относятся к приложению.
- Независимый обзор текущих исходников и границ доверия обнаружил риск чрезмерной обработки DOCX. Добавлены предварительная проверка распаковки/CRC, пределы размера/числа записей, двухминутный таймаут и ограничения захвата stdout/stderr. Синтетический сжатый DOCX с 65 МБ XML отклоняется до запуска конвертера; тесты проверяют остановку зависшего и слишком многословного процесса. Это не квота памяти/диска ОС.
- ZIP обновлён с 2.6.1 до 9.0.5 после проверки [RustSec 0367](https://rustsec.org/advisories/RUSTSEC-2026-0367.html), [0368](https://rustsec.org/advisories/RUSTSEC-2026-0368.html), [0369](https://rustsec.org/advisories/RUSTSEC-2026-0369.html). Приложение не использует затронутые `extract` API и не переносит Unix-права, но выпуск использует исправленную версию. Восстановление дополнительно ограничивает фактически прочитанные байты, проверяет имена и отклоняет символические ссылки; для ссылки с допустимым именем вложения добавлен тест.
- Актуальная проверка `npm audit`: 0 известных предупреждений, включая dev-зависимости. OSV querybatch для 253 точных Rust-пакетов после обновления: 0 совпадений. Это проверка базы известных проблем, а не аудит всех реализаций зависимостей.
- В настоящей release-сборке WebView2 созданы тестовая книга, русский абзац и автоматическая ZIP-копия; текст сверен с реальным `project.json`. Подготовка конвертеров из пользовательской папки прошла загрузку официальных архивов, SHA-256 и распаковку; сохраняются также COPYRIGHT/NOTICE.
- Публичный ZIP содержит оптимизированный EXE, инструкции RU/EN, MIT, уведомления зависимостей и скрипт подготовки. Конвертеры, рукописи, временные файлы, инструменты разработки и локальные QA-данные в него не входят. Для импортов/экспортов после скачивания нужна однократная подготовка с интернетом; обычная работа затем локальная.
- Собраны тексты лицензий 297 пакетов зависимостей, включая консервативный набор build/test-пакетов Rust. Файлы репозитория отбираются явно; артефакт Windows публикуется отдельно в GitHub Releases.

Статический обзор не исполнял вредоносные DOCX. После него выполнены перечисленные небольшие синтетические регрессионные тесты. Граф MCP в этой проверке недоступен; использовались прямые исходники. Бинарники конвертеров и внутренний код всех зависимостей целиком не аудировались.

## Проверено в настоящем окне Windows

- Стартовый экран и тёмная системная тема визуально просмотрены.
- Создание книги через нативный выбор папки прошло. Создана отдельная папка `qa/output/native/Проверка Windows`.
- Русский текст введён в настоящий WebView2-редактор через клавиатурный ввод. Статус сохранения и содержимое реального `project.json` сверены.
- При первом сохранении создан полный автоматический ZIP в соседней `StoryLens backups`.
- DOCX экспортирован через настоящее меню и системный диалог сохранения. Текст прочитан обратно Pandoc и совпал с тестовым абзацем.
- Процесс с сохранённой тестовой книгой принудительно завершён. Затем запущена **переносимая release-сборка** из `release/StoryLens`, через нативный диалог повторно открыта та же книга: блокировка освобождена, русский текст полностью сохранился, статус — «Сохранено».
- Проверка штатного закрытия выявила недостающее разрешение `core:window:allow-destroy`, нужное текущему `onCloseRequested`. Разрешение и обработчик исправлены, добавлены два браузерных регрессионных теста. В окончательной release-сборке введена ещё одна правка, нажато Alt+F4: процесс завершился, последняя правка подтверждена в JSON.
- ZIP переносимого приложения проверен чтением всех записей и CRC; в комплекте присутствуют EXE, оба конвертера, лицензии и инструкция. DOCX и EPUB из тестов также прошли проверку ZIP/CRC.

Граф MCP всё ещё относится к удалённому прототипу (поколение 2026-09-29). Новые файлы имеют `not_tracked`; проверка реализации основана на текущих исходниках, сборке и перечисленных тестах, а не на старом графе.

Снимки браузерных сценариев: `qa/output/editor-materials.png` и `qa/output/small-window.png`. Тестовый нативный DOCX: `qa/output/native-export.docx`. Эти данные не включены в пользовательскую сборку.

Обновление панели оформления: для всех `select option` явно заданы фон и цвет текста текущей темы. До исправления тесты фиксировали прозрачный фон при светлом тексте тёмной темы; после исправления обе темы проходят проверку. Обработчик выравнивания не менялся. Добавлена кнопка « » для русских кавычек; выделение всей главы через Ctrl+A также поддерживается.

В обновлённой переносимой сборке раскрыт настоящий список выравнивания Windows/WebView2 в тёмной теме: все четыре пункта читаемы, светлый текст отображается на тёмном фоне. Светлая тема проверена автоматически; системная тема Windows при проверке не менялась.

## Что ещё не подтверждено

- Чистая Windows, отсутствие WebView2, установка Runtime, SmartScreen, цифровая подпись и другой компьютер.
- Реальное отключение питания, физическая неисправность диска и заполнение пользовательского диска. Есть воспроизводимые файловые ошибки и обрыв до commit в тестах.
- Полный путь через каждый нативный диалог импорта, всех форматов экспорта и восстановления ZIP. Ядро всех операций проверено отдельно; нативно пройдены создание и DOCX-экспорт.
- Вставка из установленного Word, реальные рукописи пользователя, сложные DOCX, длительная работа с большой книгой, большие вложения и внешний просмотр EPUB в нескольких читалках.
- Самодостаточный публичный комплект с включённым Pandoc EXE не подготовлен: публичный выпуск получает конвертеры непосредственно у upstream через отдельный явный шаг, описанный выше.

Программа сохраняет рабочие данные открытым текстом. Шифрование не включено в принятый объём. Автоматические копии не ограничены по количеству и находятся на том же диске; для защиты от его поломки нужна ручная копия на другой носитель.
